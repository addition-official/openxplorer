SUMMARY
Google Drive can now be written to, but only after turning on a new setting. Off (the default) it stays read-only exactly as before, and the GIO adapter itself now also refuses every write to the drive. OneDrive stays read-only either way.

VISIBLE CHANGES
- Settings > Files & folders: a new group "Google Drive" (after "Deleting") with one switch, "Allow changes to Google Drive", off by default. It is NOT part of "Behave like Windows Explorer".
- With the switch on, in an ordinary Google Drive folder (My Drive and its folders, a shared drive's folders, folders inside Shared with me):
  - New menu (New folder, New text document, ...), Paste, Paste into, drag and drop in, Cut, Rename (F2), Delete, Shift+Delete and Duplicate are enabled as in a local folder.
  - Copies and moves in and out work with the normal progress window, Cancel, and the normal Skip / Keep both / Replace question.
  - Delete asks Windows' "Are you sure you want to permanently delete this file?" (folder / N items variants), because GVfs has no Trash for Google Drive.
  - Rename changes the item's title; Undo gives the old title back.
- With the switch on, the account's top folder, Shared with me itself and the list of shared drives still take nothing, and My Drive / a shared drive / an item listed directly in Shared with me cannot be moved, renamed or deleted.
- With the switch off, the disabled commands now explain how to turn writing on (new tooltip text below) instead of saying "read-only for now". OneDrive keeps the owner's message.
- The new preference is saved as "allowGoogleDriveChanges" in settings.json only when on, and is included in Export/Import settings like every other preference.

HOW THE GVFS GOOGLE QUIRKS ARE HANDLED
(Read from gvfsbackendgoogle.c, GVfs 1.54; the Ubuntu 24.04 package here is 1.54.4.)
- IDs vs titles: GVfs names items by Drive ID; a title in an address is looked up and reported as a symlink ("volatile"). Queries on google-drive:// now follow links (Drive has no real links), and created/renamed/landed items are recorded by their ID address, so Undo never hits a same-titled neighbor.
- Same titles: Drive allows two items with one title. The app never creates a duplicate: a taken title is a name conflict (Skip / Keep both / Replace). Replace onto a title two items share is refused.
- Replace: never GVfs's overwriting move (it deletes the old file permanently after the move). The old file is renamed to a private title, the new one renamed into place, then the old one deleted.
- Uploads: built under a private ".winspace-transfer-<hex>.part" title beside the final title, then renamed in place (works on every GVfs version). The uploaded size is checked against the source first. Note: that private title is briefly visible on drive.google.com while a copy runs.
- Moves across folders: newer GVfs moves natively (same ID). Older GVfs refuses; the app then asks to finish the move by copying (existing question), copies, checks, and only then deletes the original.
- Trash: GVfs reports access::can-trash = false and its delete is permanent (Drive API delete, not Drive's trash). So Delete asks for a permanent delete; Trash is never silently turned into a delete.
- Slashes in titles: copies off the drive use GVfs's copy name ("/" becomes "-"; a duplicate title gets " - <ID>" before the extension).
- Docs/Sheets/Slides: GVfs lists them as shortcuts. Copying is refused with the message above; nothing is written, not even 0 bytes. Moving a Doc within the drive works.
- Big files: progress and Cancel through the normal progress window; a canceled or failed upload's partial staging file is deleted.
- Quota: GVfs turns Google's quota refusal into "Permission denied"; the adapter re-checks the drive's free space and reports the full-drive message. The free-space precheck also runs before copying.
- Offline: GVfs passes libsoup/resolver messages as plain failures; these (and network error codes) become "The network location cannot be reached."

HOW TO TRY IT SAFELY ON YOUR REAL DRIVE
1. Keep a backup of anything important: Delete on Google Drive is permanent here; it does not go to Drive's trash. (Workspace admins can sometimes restore within 25 days; personal accounts cannot.)
2. In a browser, on drive.google.com, make a new folder "OX test" in My Drive and put two or three throwaway files in it. Do not test in folders with real files.
3. In OpenXplorer, open Settings > Files & folders > Google Drive and turn on "Allow changes to Google Drive".
4. Open Google Drive in OpenXplorer, go into "OX test" only, and try: New folder, New text document, copy a small file from this PC in, copy it again (choose Keep both), rename one, copy a file back to this PC, then delete one test file (you will be asked first).
5. Check the result on drive.google.com after each step (refresh the page).
6. Try a bigger file (a few hundred MB) and press Cancel halfway: nothing should be left in "OX test" (on drive.google.com a ".winspace-transfer-....part" file may appear briefly while copying and must be gone after Cancel).
7. Try copying a Google Doc to this PC: you should get the "exists only online" message and no file.
8. When done testing, turn the switch off again until you are confident; with it off, nothing in OpenXplorer can change your Drive.
