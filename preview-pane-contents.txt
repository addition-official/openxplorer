The failing tests came first in their own commit (7f85637d) and failed before the fix: a recording on a share, a Recent row's recording and a remote recording with previews off (content.rs), and a pane hidden while it reads (contents.rs). P1: an audio or video file's player now gets the file it stands for (a Recent row's target, or an smb:// file through its CIFS mount or GVfs FUSE export) under the same network rule as text, pictures and PDFs. With network previews off, a remote folder, item or SMB file gets no player. For any other path, the path is found and checked against network file systems (NFS, CIFS, sshfs, rclone, GVfs FUSE) off the UI thread before GtkMediaFile opens it. The Details pane's player follows the same rule, since it is the same widget. Because the player now appears only after that check, the existing test recordings_get_a_player_that_starts_only_with_auto_play waits for it. P2: when the pane is closed or hidden by a narrow window, its wait and read are cancelled and the page is invalidated, so no further PDF batches start. The page it was asked for is kept and read again when the pane is shown.
