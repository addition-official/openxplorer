Earlier NOTE: A revisited folder shows its thumbnails at once, as Windows does from thumbcache, from the freedesktop shared cache (normal, large, x-large, xx-large; MD5 of the URI).
- Lookup: the app reads the cache first, itself. It parses Thumb::URI, Thumb::MTime and Thumb::Size (when present) from the PNG text chunks in safe Rust, without decoding. A larger size stands in for a smaller one. GIO's thumbnail::* query is now used only for files without a known time.
- Batched reads: current entries are decoded in the sandboxed decoder pool, 12 per request to one decoder, each answer handed back as it comes. A crashing picture is refused alone and the rest of its batch goes to a new decoder.
- Memory: a 64 MB LRU of shown thumbnails (kept at the size shown, about 2,700 Large-icon photos), checked against mtime and size, draws a same-session revisit on the tile's first frame, also with network previews off (the default) however long ago the folder was found local.
- No icon flash: the cache's entry names are listed in the background once a view with thumbnails is set up (as 128-bit numbers: 5.6 MB for 200,000 entries), so a tile whose entry exists hides its type icon (250 ms at most) until the read lands. Decoders start in the background then too. Thumbnails show as soon as they are read; a custom icon found later replaces one.
- Generation: off the main thread, on one fewer slot than the processors (2 to 3, was 2), with tiles on the screen first (GTK binds about 190 for 30 visible). A cell counts as on screen only once it is laid out. A new photo costs 1 decode instead of 3.
- Writes: 0600 temp file (O_EXCL, O_NOFOLLOW) in 0700 folders, renamed into place, with Size and Mimetype keys.
- Failures: damaged pictures, and files a desktop thumbnailer ran to the end on and gave up on, go to thumbnails/fail/openxplorer. With gnome-thumbnail-factory's failures, they are not retried until the file changes.
- Moves: a file the app moves or renames (via the undo journal, so Undo and Redo too), and every file of a moved folder up to 5,000, keeps its entries. The keys are rewritten with the pixels untouched; an entry from another version is left alone.
