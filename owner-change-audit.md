## How this was checked

- Every user-visible diff was read with git at its merge commit, and the code was re-checked at `3ef87f79` for whether it is still there and for risk (main-thread file I/O, unwrap/expect/indexing on file or network data, changed defaults). File:line references are at `3ef87f79`.
- Live checks: a release build of `3ef87f79` (`cargo build --release -p ox-app`), run as the unprivileged user `tester` with a throwaway HOME and XDG directories, in a private `dbus-run-session` on a private Xvfb (`:77`, 1400x900, GTK 4.14.5, X11 backend), driven with real XTEST input through xdotool. No live desktop and no real user data were used. Results are quoted in the rows for #29, #162, #209, #212, #214 and #374.
- Not checked: anything needing a network share, SMB server, polkit, Flatpak, Wayland or a non-en_US locale (the container has no other locale installed). No tests from `native/tools/check.py` or `native/parity/check.py` were run, because no code was changed.
- Windows 11 verdicts come from knowledge of Windows 11 22H2 to 24H2 File Explorer; anything uncertain is "needs VM" with steps. No Windows VM was used.

## Crashes found during the live checks

1. **Segfault on file drag and on a refused rename character when `GTK_A11Y=none` is set.** `announcement::announce` (`native/crates/ox-app/src/announcement.rs:18-26`, added in #29) skips only `GtkTestATContext`. With `GTK_A11Y=none` on GTK 4.14.5, calling it segfaults (gdb: `ox_app::announcement::announce::<gtk4::Label>`). Reproduced twice each:
   - start dragging any file in the file list (`BrowserWindow::begin_file_drag`, `window/file_drag.rs:573`, from #29);
   - press F2 on a file and type `:` (`Balloon::show`, `window/file_ops/name_balloon.rs:153`, from #212).
   The status bar hint (`status_bar.rs:302`) uses the same helper and is likely affected too (not reproduced). With `GTK_A11Y` unset (no accessibility bus), neither crashes. `GTK_A11Y=none` is a documented GTK setting that some users and distributions set to avoid AT-SPI slowdowns, so this is a plain fix: also skip when the widget has no AT context or when `GTK_A11Y` is `none`, and add a test that runs with `GTK_A11Y=none`.
